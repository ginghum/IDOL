# IDOL — LIVE DUEL

3人組アイドルを編成し、共有の観客を獲得して20ポイントを目指すカードゲーム。現在はCPU対戦のみ。

公開先: https://ginghum.github.io/IDOL/

## 遊び方
1. 6人から3人を選び、リーダーを1人選択。
2. 専用・共通からイベント3枚と先攻・後攻を選び「CPUとライブを始める」。カットインで自分のリーダースキルを確認して「ライブ開始」。
3. 手札を選択し、指定メンバーを含む必要人数を選んでvol / fanのどちらかを使用。
4. ファンサービス、応援チップ、メモリーを払うイベントを組み合わせて観客を獲得。

詳細はゲーム内「遊び方」「カード一覧」を参照。イベントのメモリー支払い・独占チップ・華の累積効果まで実装しています。ブラウザに自動保存され、編成画面の「続きから」で再開可能です。

## 構成
- index.html: 外部依存なしの単一HTML。CSS、DOMに依存しないルールエンジン、UIを分離して記載。
- tests/game.test.mjs: 個別ルールとCPU同士300試合を検証。Node.jsで `node tests/game.test.mjs`。
- GitHub Pages: mainブランチのルートを公開。

カード・メンバーの画像は同梱したWebPを使用します。画像追加時はindex.html内のARTWORKにURLを登録してください。キーは idol-kayo、song-kayo-1、event-kayo、fan-core の形式です。

## 試作で補った処理
- 専用6種類・共通4種類から異なる3枚を選択し伏せる。専用イベントには対応メンバーのメモリーが必要。手札上限なし。
- 勝敗は一連の効果完了後。20点の勝利判定を山札・手札切れの敗北より先に行う。
- 観客効果は獲得した全員分が発動。厄介なファンで戻した観客の効果も消えない。同点の戻し先は獲得側が選ぶ。
- 雷の選択獲得は通常獲得全体を1枚に置き換える。通常獲得枚数の加算は適用しない。
- 雷の交換イベントはデッキにコアファンがあり、交換可能な観客がいる場合に使用可能。
- 麻智の開始時効果はターン開始のドロー後。相手の独占チップ付き観客は選択不可。
- 時尾のイベントはvol180%以上で使用可能。一時点はターン終了で消える。
- 独占チップは雷リーダーなら開始時に手元へ用意。観客がゾーンを離れると回収。
- 華の強化は応援チップ効果1回につき+1。次のfanモードまたは佳代のイベントで消費。volモードでは残る。ターン終了時に失う。

## 今後のオンライン対応
ルールエンジンはJSONの状態とコマンドを扱い、サーバー側へ移しやすい構成です。現時点はブラウザ内のCPU戦で、オンライン通信・アカウント登録・サーバーはありません。オンライン化時には非公開情報の分離とサーバー側検証を追加してください。

## 共通イベント
- やり直し：3メモリー。観客ゾーンをデッキに戻してシャッフル・補充。相手の独占チップ付き観客は保護される。
- センタースイッチ：3メモリー。別メンバーにリーダー交代。前の能力による独占チップ・未消費の華の強化を除去。初期vol・手札は再適用しない。
- 会場トラブル：4メモリー。自分の獲得観客をランダム1枚、その後相手の観客をランダム2枚戻す。不足分は存在する枚数まで処理。
- 機転：2メモリー。手札1枚をメモリーへ置いて1ドロー。各自のターン1回、再使用可。

メモリーの支払いは合計指定枚数ちょうど。指定メンバーの枚数は最低必要枚数。UIは合計上限を超える追加選択を拒否し、ルールエンジンも過不足のある支払いを拒否する。



## カードイラスト

メンバー立ち絵6点、専用楽曲18点、専用イベント6点、共通イベント4点を `assets/art/` に収録。全34点はWebP形式、合計約3.9 MiB。`index.html` の `ARTWORK` で対応付けています。

「君と私の平和条約」は海辺の新構図、「遊楽道中」は橋を渡る横向き全身の描き直し版を使用。アルバム画像は正方形の全体を表示し、立ち絵は全身が収まる表示です。メモリーや手札を選ぶ際の小さな画像も同じ対応を使用します。


## 対戦卓UI

PCでは相手・観客・自分・手札を1画面に固定配置。スマホ縦持ちではカード束とイベントをタップメニューにまとめ、手札のみ横スクロールします。楽曲を選択すると、手札エリア内でVOL/FANを選び、盤面のメンバーをタップして行動人数を変更できます。観客の緑枠は通常FAN獲得対象のプレビュー。画像は観客5種類を加えて計39点です。

ドロー、楽曲のメモリー移動、観客獲得と補充をアニメーション表示し、CPUは使用カードとモードを表示します。詳細は観客・メンバー・カード束をタップして確認でき、イベント支払いは従来どおり指定枚数ちょうどです。

検証: `node --test tests/*.test.mjs`。盤面UI、相手の伏せ札の秘匿、手番制限、画像39点の存在と、既存の対戦シミュレーションを確認。ブラウザでは1363×936、390×844、375×667、844×390で確認。

## 編成と開幕演出

編成は6人の立ち絵カード、3人のユニットプレビュー、リーダースキル、イベント選択を表示。スマホではメンバー→リーダー→イベントの順に並べます。開始カットインは両リーダーと自分のリーダースキルを表示し、開始ボタンで進行。CPU先攻でも確認中は行動しません。

観客山札は列の末尾側（右）に配置。メンバー詳細は全身用の画像枠を使用。行動通知は1度表示すると消費し、カードや行動メンバーの選択で「ターン交代」が再表示される不具合を修正しました。

## スマホの手札表示

観客の下の余白と自分のメンバー領域を詰め、手札領域とジャケット画像を拡大。左右の薄い矢印はタップで手札を送れ、スワイプと併用可能。端では該当矢印を薄くし、横送り不要なら非表示。楽曲選択中は矢印も隠します。
